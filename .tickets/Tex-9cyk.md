# 全アプリ一覧内の検索

一覧を開いた状態で検索フィールドをタップすると、一覧内の検索になる。
- 並び順、Enter での起動、学習の記録は通常の検索と同じ
- 結果はフィールドの直下から上詰め（1位がフィールドに一番近い）
- 戻る操作は普通の挙動: 1回目でキーボードを閉じる（入力は残す）、2回目で一覧を閉じる
- この間は 1.4 のキーボード監視をしない
仕様: docs/spec.md 6.5

## Launcher3 からの移植

- 一覧と検索結果の切り替えにアニメーションは付けない（docs/spec.md 6.5）

## Acceptance Criteria

- [x] 一覧でフィールドをタップ → キーボードが出て、入力で一覧が絞り込まれる
- [x] Enter → 1位が起動する
- [x] 戻る1回目 → キーボードだけ閉じ、絞り込みは残る
- [x] 戻る2回目 → 一覧が閉じ、通常のホームでキーボードが出ている

## 結果（2026-11-22）

- 一覧を開いた状態でフィールドをタップすると、フォーカスが当たってキーボードが出る。入力すると、ハンドル付きシートの中で一覧が検索結果に置き換わる（アニメーションなし。上流のコンテナの検索用 RecyclerView にあたる）
- 検索結果は通常の検索と同じ SearchResults（並び順、Enter での起動、学習）を、シートの上で上から並べる設定（inAllApps）で使う。文字はシートの上の BaseIcon.AllApps の見た目。下の余白はキーボードかナビゲーションバーの高さ
- 戻る1回目: キーボードが閉じ、入力と絞り込みはそのまま、フォーカスは外れる（キーボード監視の代わりに、一覧内の検索中はフォーカスを外すだけ）。2回目: 一覧が閉じて入力がクリアされ、通常のホームでキーボードが出る
- 結果が選ばれた状態で文字を打つと、一覧内ならフィールドにフォーカスを戻すだけ（キーボードは一覧を閉じずに入力を受ける）
- エミュレータで確認: タップでキーボード、入力で絞り込み、Enter（日本語入力の確定のあと）で1位が起動、戻ると一覧は閉じている、戻る2回の動き
