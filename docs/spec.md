# TextLauncher 仕様書

## コンセプト

常にキーボードが表示されている、テキスト入力中心の Android ホームアプリ（ランチャー）。

- ホーム画面では常に検索フィールドにフォーカスが当たり、キーボードが表示されている
- 入力した文字でアプリをインクリメンタルサーチし、Enter で即起動する
- 未入力のときは、ユーザーが自由に配置したアプリ・ウィジェット・フォルダが表示される

前提環境は minSdk 37 / targetSdk 37。

---

## 1. 検索フィールドとキーボード

### 1.1 常時フォーカス

検索フィールドには常にフォーカスが当たり、キーボードが表示されている。以下のタイミングでフォーカスを当て、キーボードを表示し直す。

| タイミング | 主なフック |
|---|---|
| アプリからホームに戻ったとき | `onResume` |
| ホーム画面上でホームボタンを押したとき | `onNewIntent` |
| ロック解除後、通知シェードを閉じた後など、ウィンドウにフォーカスが戻ったとき | `onWindowFocusChanged(true)` |
| ホーム画面が前面のままキーボードが閉じられたとき | IME 表示状態の監視（[1.4](#14-戻る操作) を参照） |
| 編集モードが終わったとき | [5.4](#54-編集モード) を参照 |
| 全アプリ一覧を閉じたとき | [6.6](#66-閉じる操作) を参照 |

例外として、次の間はキーボードを下ろし、フォーカスも外す。

- 編集モード中（[5.4](#54-編集モード)）
- 全アプリ一覧を開いていて、ユーザーがまだ検索フィールドをタップしていない間（[6.4](#64-開いた状態)）

### 1.2 入力のクリア

- ランチャーが前面に戻るたびに入力をクリアする（アプリから戻る、ホームボタン、ロック解除のいずれも含む）
- アプリを起動したときもクリアする。ただし起動したアプリが画面を覆ってから（ランチャーが見えなくなってから）クリアし、起動の途中でホームの配置が見えないようにする
- 戻る操作をしたときもクリアする（[1.4](#14-戻る操作) を参照）

### 1.3 配置と見た目

- 検索フィールドはキーボードの直上に置く（IME の inset に追従させる）
- フォーカスが当たっていることが UI で分かるようにする
- Enter で起動される候補（検索結果の1位）にはフォーカス枠を付ける（[2.6](#26-キーボードフォーカス) を参照）

### 1.4 戻る操作

戻るジェスチャーは完全には禁止できない。以下の方法で実質的に無効化する。

1. **Activity の戻る操作**
   `OnBackPressedCallback` で消費し、何もしない。
2. **キーボードが閉じる動作**
   キーボード表示中の戻る操作はキーボード（IME）側が先に受け取って自分を閉じるため、アプリからは止められない。そこで、ホーム画面が前面にある間にキーボードが閉じられたことを検知したら、入力をクリアしてすぐに表示し直す。結果として、戻る操作は「入力クリア」として働く。長押しメニューかフォルダが開いていれば、Launcher3 の戻る操作と同じくそれも閉じる（長押しメニューが優先で、一度に閉じるのはどちらか一方）。閉じるアニメーションが一瞬見える可能性がある。
3. **ジェスチャー除外領域**（`setSystemGestureExclusionRects`）
   使わない。除外できるのは各辺で縦 200dp までで、しかも対象はアプリ自身のウィンドウだけなので、キーボードの領域には効かない。

## 2. アプリ検索

### 2.1 検索対象

- 検索対象はランチャーに表示されるアプリ（`LauncherApps.getActivityList`）のみ
- 対象は個人用プロファイルのアプリだけ。仕事用プロファイルと Private Space には対応しない（[8. 対象外](#8-対象外としたもの) を参照）
- アプリごとの照合文字列は次の2種類
  - アプリ名（ラベル）
  - ユーザーが設定した検索文字列（1つのアプリに複数設定できる。[4. 検索文字列の編集](#4-検索文字列の編集) を参照）
- アプリショートカット、連絡先、設定項目、Web 検索、フォルダなどは検索対象にしない（[8. 対象外](#8-対象外としたもの) を参照）

### 2.2 正規化

入力文字列と照合文字列の両方に、同じ正規化をかけてから比較する。

1. NFKC 正規化（全角英数字を半角に、半角カナを全角に揃える）
2. 小文字化
3. カタカナをひらがなに変換（`ァ`(U+30A1)〜`ヶ`(U+30F6) から 0x60 を引く）

これにより、カタカナのアプリ名や検索文字列は、ひらがなで入力しても一致する。漢字の読みは自動では取得しないので、ユーザーがひらがなの検索文字列を登録して補う。

### 2.3 並び順

入力文字列 `q`（正規化済み）に対して、各アプリの照合文字列のうち最も強い一致の種類を、そのアプリの一致種別とする。

| 一致種別 | 条件 |
|---|---|
| 完全一致 | 照合文字列 == `q` |
| 前方一致 | 照合文字列が `q` で始まる |
| 部分一致 | 照合文字列が `q` を含む |

候補は次の優先順位（グループ）で並べる。

1. **完全一致**：グループ内は学習スコアの降順
2. **学習あり**：完全一致以外で、`q` に対する学習スコアが 0 より大きいアプリ。スコアの降順
3. **前方一致**
4. **部分一致**

3と4のグループ内はアプリ名順で並べる。アプリ名順は全アプリ一覧（[6.4](#64-開いた状態)）と同じく Launcher3 の `LabelComparator`（英字・数字などの文字で始まる名前が先で、端末の言語の照合順）。

> 学習スコアは `q` と完全に同じ入力文字列で起動した記録だけを使う。`q` を先頭に含む別の入力（たとえば `q` が `s` のときの `sl`）の記録は使わない。

### 2.4 Enter で起動

- 候補の1位を Enter で起動する（IME のアクションは `actionGo`）
- 日本語 IME で変換中に押した Enter は確定として扱われ、起動はしない（IME 側の標準動作）
- 候補が0件、または未入力のときは何もしない
- 候補をタップしても起動できる

### 2.5 検索結果の表示

- 入力があるときは、ホームの配置エリアの代わりに検索結果を表示する
  - ホームと検索結果の切り替えにアニメーションは付けない。入力に即座に反応させるため。Launcher3 の SearchTransitionController は取り込まない
- 見た目は Launcher3 のアプリ一覧と同じグリッドにする。各セルはアイコンと、その下のアプリ名
  - 列数は、ホームのグリッド（[5.1](#51-グリッド)）と同じ
  - ホームの配置ではアプリ名を出さないが、検索結果では出す
- 下寄せにし、1位を検索フィールドに一番近い位置（一番下の行の左端）に置く。2位以降は右へ並べ、行が埋まったら上の行に続ける

### 2.6 キーボードフォーカス

- 検索結果、ホーム、フォルダの中のアイテムは、Launcher3 と同じく物理キーボードなどの矢印キーで選べる。フォーカス枠は、見た目も動きも Launcher3 のもの（角丸 16dp、2dp の二重線。色はテーマに合わせる）
- 入力が変わるたびに、1位（Enter で起動される候補）に枠を付ける。キーボードのフォーカスは検索フィールドに置いたままで、枠だけを付ける
  - Pixel Launcher の検索に合わせたもの。AOSP の Launcher3 にはない（Launcher3 は1位を Enter の対象として覚えるだけで、枠は出さない）
- 矢印キーで検索フィールドからフォーカスを移せる。枠はフォーカスに付いて動き、Enter でそのアイテムを起動する（フォルダは開く）
- フォルダをキーで開いたときは、Launcher3 と同じくフォーカスがフォルダの最初のアイテムに移り、矢印キーでフォルダの中のアイテムを選べる。閉じるとフォルダのアイコンに戻る。タッチで開いたときは検索フィールドがフォーカスを持ったまま（キーボードも出たまま）
- アイテムにフォーカスがあるときに文字を打つと、検索フィールドにフォーカスが戻り、その文字が入力される（Launcher3 と同じ）
- アイテムにフォーカスがあるとキーボードは下りる。このときの戻る操作は、[1.4](#14-戻る操作) と同じく入力をクリアして検索フィールドに戻す（フォルダが開いていれば、先にフォルダを閉じる）

## 3. 起動の学習

### 3.1 記録する内容

検索結果からアプリを起動したとき、次の組み合わせを記録する。

`(正規化済みの入力文字列, アプリ) → (score, lastUpdated)`

- アプリは `ComponentName` と `UserHandle` で識別する
- 未入力状態のホーム配置から起動した場合は記録しない

### 3.2 スコア（直近ほど重くする頻度）

起動回数をそのまま使うのではなく、時間とともに減衰するスコアを使う。半減期を `H` とする。

- **起動したとき**：`score = score × 0.5^((now − lastUpdated) / H) + 1` を計算し、`lastUpdated = now` にする
- **並べ替えるとき**：その時点の値として `score × 0.5^((now − lastUpdated) / H)` を使う

この方式の特徴は次のとおり。

- 起動履歴を全件保存しなくても、1レコードあたり2つの値で「回数」と「新しさ」の両方を表せる
- しばらく使わなかった組み合わせは自然に順位が下がる
- `H` の初期値は 14 日とし、使いながら調整する
- 計算後のスコアが一定値（例: 0.05）を下回ったレコードは削除する

## 4. 検索文字列の編集

- アプリごとに検索文字列を複数登録・削除できる
- 編集画面を開くと、追加用のフィールドにフォーカスが当たり、キーボードが出る。登録した文字列は右の × で消せる
- 編集の入口は、アプリの長押しメニューの「検索文字列を編集」（[5.3](#53-編集操作launcher3-に準拠)）。ホーム、検索結果、全アプリ一覧のどこからでも開ける
- 設定画面は置かない（[8. 対象外](#8-対象外としたもの)）。見た目の設定は「壁紙とスタイル」に任せる（[7. アイコンとテーマ](#7-アイコンとテーマ)）
- 登録した文字列は [2.2](#22-正規化) と同じ正規化をかけて照合する。カタカナで登録しても、ひらがなと同じように扱われる

## 5. ホームの配置（未入力時）

ユーザーが任意のアプリ、ウィジェット、フォルダを配置できる。基本は AOSP の Launcher3 の標準的な設定と操作に合わせ、以下に書いた点だけを変える。手触りに関わる部分は Launcher3 の実装を持ってくる（[Launcher3 からの取り込み方針](launcher3-porting.md)）。

### 5.1 グリッド

- 列数、アイコンサイズ、セルの幅は、Launcher3 の標準のグリッド設定（`res/xml/device_profiles.xml` の `grid-option`）に合わせる。選び方も Launcher3 の `InvariantDeviceProfile` と同じで、端末の種類（スマホ、折りたたみ、タブレット）に合う候補（`display-option`）の中から、端末の幅と高さに一番近いものの列数を使い、アイコンと文字の大きさは近い3つの候補を距離で重み付けして平均する（`invDistWeightedInterpolate`）。たとえば Pixel 6a は 5列・アイコン約56dp になる。Pixel Launcher は Google 独自の設定（Pixel 6a では4列・66dp）を使うので、アイコンの大きさは揃わない
  - Launcher3 と同じく、アイテムを置いたグリッドの列数（`DeviceGridState`）と同じ列数の候補があれば、その中から選ぶ（`filterByColumnCount`）。表示サイズやナビゲーションの方式を変えても、できるだけ列数を保つ（行数は変わりうる）
  - Launcher3 と違い、選んだグリッドの名前（`GRID_NAME`）を覚えておかず、毎回ディスプレイから決め直す。グリッドを選ぶ設定もない。タブレットのグリッドは画面に合わせた伸縮（`isScalable`）をしない
- アプリ名は表示しない。その分、セルの高さを詰める（アイコンと余白だけ）
- 配置できる範囲は、Launcher3 のホームの1ページと同じく、ステータスバーの下からホットシート（このランチャーでは検索フィールド）の上まで。キーボードを下ろした状態で測る
  - 行数は、その高さに入るだけ（高さをアイコンと余白の高さで割って切り捨て）。セルの高さは、Launcher3 と同じくその高さを行数で割ったもの
  - Launcher3 は行数をグリッドの設定（`numRows`）から決めるが、アプリ名を出さないこのランチャーではセルが縦に間延びするので、入るだけの行数にした
  - 列数と行数は、Launcher3 の `InvariantDeviceProfile` と同じく、今のウィンドウではなく端末のディスプレイで決まる。内蔵ディスプレイのどれでも、どの向きでも使える一番小さい幅と高さ（ステータスバーとナビゲーションバーを除いた見積もり。スマホの横向きは縦横を入れ替えて数える。2パネルの画面（[5.5](#55-2パネル折りたたみ端末の内側)）は半分の幅で数える）から計算するので、画面の回転、折りたたみ、分割画面、キーボードでは変わらない
    - 使っていない内蔵ディスプレイ（折りたたみ端末の外側と内側のうち、今使っていない方）の大きさは、`DisplayManager.DISPLAY_CATEGORY_BUILT_IN_DISPLAYS`（Android 16 QPR2 で追加）で取る。これを使うために minSdk を 37 にした（AGP の minSdk には 36.1 を書けない）
    - ホームを出せないほど小さい内蔵ディスプレイ（Launcher3 の一番小さい設定の 255×400dp に満たないもの。縦に折る端末の外側の小さい画面など）は数えない
    - 大画面のカットアウトは、どの向きでも上にあるものとして数える。角にあるカットアウトは回転しても上の辺に残ることがあり、Launcher3 の見積もりのように向きに合わせて回すと、起動したときの向きでグリッドが変わってしまうため
  - ウィンドウがディスプレイの行数より低いとき（分割画面）は、セルを一番小さい高さのままにして縦スクロールする。Launcher3 はホーム全体を縮めるが、このランチャーはもともとキーボードの裏を縦スクロールで見せるので、それに合わせた
  - キーボードが出ている間は見えている範囲が狭くなるので、縦スクロールする。スクロールできるのはアイテムのある一番下の行までで、その下の空いた行はキーボードの裏に隠れたままにする。範囲そのものは伸びない
  - 範囲の外にあるアイテムや、ほかのアイテムと重なっているアイテムは、Launcher3 と同じく読み込むときに削除する（`LoaderCursor.checkItemPlacement`）
  - グリッドが変わったとき（表示サイズやナビゲーションの方式の変更、別のディスプレイ）は、Launcher3 の `GridSizeMigrationLogic` と同じく、読み込む前にアイテムを新しいグリッドへ移す。列が同じで行が増えたときは、増えた行を上に足して全体を下にずらす。それ以外は、上の行の左から順に詰めて置き直す。入りきらなかったアイテムは、Launcher3 なら新しいページに置くが、ページが1つなので削除する
- 画面の向きは Launcher3 の `RotationHelper` と同じ。スマホでは自動回転がオンでもホームは縦（端末の自然な向き）のまま。大画面の端末（短い辺が 600dp 以上）では回転する。ドラッグ中は向きを固定する
- 縦スクロールできるときは、右端にスクロールバーを出したままにする。色と太さは全アプリ一覧のスクロールバーに合わせる（Launcher3 のページインジケーターの代わり）
- キーボードが表示されているぶん配置エリアは狭くなるが、初期実装では対策しない。実際に作ってから判断する

### 5.2 配置できるもの

- **アプリ**：1セルを使う。アプリ名は表示しない
- **アプリのショートカット**：アプリの長押しメニューから置く（[5.3](#53-編集操作launcher3-に準拠)）。1セルを使い、アイコンの隅にアプリのバッジを付ける（Launcher3 と同様）。名前は表示しない。タップで起動する。置いている間はシステムに固定（pin）し、外すと固定も外す。アプリ側で消えたショートカットはホームからも外れる
- **ウィジェット**：複数セルを使う。`AppWidgetHost` で表示し、追加時のサイズとリサイズは Launcher3 に合わせる。ウィジェット内部のスクロールは考慮しない
  - 追加は空き領域の長押しメニューの「ウィジェット」から。Launcher3（Android 17）と同じウィジェットピッカー（Compose 版の `WidgetPickerActivity`）を開く。左におすすめ・アプリ・分類（会話など）の一覧と検索、右に選んだもののプレビューを出し、プレビューをタップすると出る「追加」でホームに置く（ピッカーは閉じる）。ピッカーからのドラッグ、アプリのショートカットの作成（`ACTION_CREATE_SHORTCUT`）、ほかのアプリからのピン留めの要求はまだできない
  - 追加するとき、ランチャーにウィジェットを作る許可がなければ、OS の確認画面（`ACTION_APPWIDGET_BIND`）を出す（Launcher3 はシステムアプリとして許可を持つので出ない）。確認画面や設定画面がピッカーを閉じるときのホームへの切り替えで消えないよう、追加の手続きはホームが前面に戻ってから始める。設定画面のあるウィジェットは、Launcher3 と同じく設定画面を経て追加する（設定を省略できると宣言しているものは経ない）。途中でやめたら追加しない
  - 置く場所は、メニューから追加したアプリと同じくホームの最初の空きセル。大きさは Launcher3 と同じく、ウィジェットが宣言する大きさをホームのセルの大きさで割って決める（`LauncherAppWidgetProviderInfo.initSpans`）。空きがなければ「このホーム画面には空きスペースがありません」と出して追加しない（Launcher3 はページを足す）
  - ウィジェットの周りには Launcher3 と同じ 6dp の余白を取る（セルの間に隙間がないため）
  - 長押しすると、Launcher3（Android 17）と同じくメニューとリサイズ枠を出す。メニューは「削除」と、設定し直せるウィジェットなら「設定」（ウィジェットの設定画面を開く）。指を離さずに動かすとメニューと枠を閉じてドラッグに移り、移動できる。削除に落とすとホームから外す
  - リサイズ枠は Launcher3 の Compose 版（`AppWidgetResizeFrameCompose`）と同じもの。枠の四辺の中央の丸いつまみをドラッグすると、セル単位で大きさが変わる（角からは縦横を同時に）。つまみをタップすると「＋／−」のボタンが出て、1セルずつ大きく・小さくできる（指1本のタップだけでも操作できるようにするための、Android 17 の変更）。ほかの項目は Launcher3 と同じく押しのける。大きさの範囲はウィジェットが宣言する最小・最大の大きさから決め（`LauncherAppWidgetProviderInfo.initSpans`）、大きさが変わるたびにウィジェットに伝える
  - リサイズ枠は、長押ししたとき、ドラッグで落とした後、追加した直後に出す（Launcher3 と同じ）。枠の外をタップすると閉じる（メニューが出ていればメニューも閉じる）。ホームがスクロールしたりキーボードで動いたりしても、枠はウィジェットについていく
  - 提供元のアプリがなくなったウィジェットは、読み込むときに削除する
- **使えない項目**：Launcher3 と同じく灰色で表示する。作成元のアプリが無効にしたショートカットは、タップで使えない旨を出す。停止中・使用制限中のアプリは、タップするとシステムが理由を示す（検索結果でも同じ）。ショートカットを問い合わせられないときは、覚えているアイコンか既定のアイコンで表示を続ける
- **アプリがなくなったとき**（Launcher3 と同じ）：アンインストールされたアプリはホームとフォルダから消す。SD カード上のアプリが一時的に使えないときは、覚えているアイコンのまま灰色で残し、タップで使えない旨を出す（使えるようになれば戻る）。アプリの起動画面が変わった（別アイコンへの切り替えなど）ときは、そのアプリの今の起動画面に付け替えて残す
- **空きがないとき**：長押しメニューの「＋」で追加しようとしたとき、ドロップしようとしたときに空きセルがなければ、Launcher3 と同じく「このホーム画面には空きスペースがありません」と出して置かない（Launcher3 は「＋」ではページを足すが、ホームは1ページなので出すだけ）。アプリに重ねてフォルダを作る、フォルダに入れることはできる
- **フォルダ**：
  - 名前は付けられない
  - アイコンは中のアプリのプレビューにする（Launcher3 と同様）
  - タップすると中身を開く。中のアプリもアプリ名は表示しない
  - 外側に触れる、戻る操作、文字の入力で閉じる。中のアプリを起動したときは、Launcher3 と同じく開いたままにし、ランチャーが隠れたときに閉じる。中のアイテムのドラッグでは閉じない（[5.3](#53-編集操作launcher3-に準拠)）
  - フォルダ自体は検索対象にしない

### 5.3 編集操作（Launcher3 に準拠）

- **アプリの長押し**（ホーム上でも検索結果でも同じ）：
  - その場にメニューを出す
  - 指を離さずに一定距離動かすと、メニューを閉じてドラッグに移る（Pixel Launcher と同じ動き）
  - メニューの項目は「検索文字列を編集」と「アプリ情報」、続いてそのアプリのショートカット（Launcher3 と同じく最大 4 つ）。ショートカットはタップで起動する
  - ショートカットは長押しでドラッグしてホームやフォルダに置ける。行の右端の「+」を押すと、ホームの最初の空きセルに置く（検索結果から押した場合は入力をクリアしてホームを表示する。全アプリ一覧から押した場合は、Launcher3 と同じく一覧をアニメーションで閉じてから置き、置いたアイコンが弾むのが見える）
  - ホームやフォルダに置いたショートカットの長押しメニューは「アプリ情報」だけ
  - メニューの見た目、位置、開閉は Launcher3 の長押しメニューに合わせる。キーボードに重ならないよう、キーボードの上の範囲に収める
- **検索結果からのドラッグ**：ドラッグが始まった時点で入力をクリアし、ホームの配置の表示に切り替える。そのままホームに置ける（Launcher3 でアプリ一覧からドラッグする操作に相当）
- **フォルダの長押し**：その場にメニューを出し、指を離さずに動かすとメニューを閉じてドラッグに移る（Launcher3 と同じ）。メニューの項目は「削除」だけで、押すとフォルダを中身ごとホームから外す
- **フォルダの中のドラッグ**（Launcher3 と同じ）：
  - 開いたフォルダの中のアイテムを長押しして動かしても、フォルダは開いたまま。後ろのホームは編集モード（[5.4](#54-編集モード)）になる
  - フォルダの上で動かすと、ほかのアイテムがよけて空きが動き（止まって 250ms）、離した位置に置く。並び順は保存する
  - フォルダの外に出すと、400ms 後にフォルダが閉じ、そのままホームに置ける。戻ってくれば閉じない
  - 落とせない場所で離したとき（取り消しを含む）は、フォルダの元の位置に戻す
  - ホームのアイテム、検索結果や全アプリ一覧のアプリ、長押しメニューのショートカットをホームのフォルダのアイコンに重ねたままにすると、800ms 後にフォルダが開き、中の好きな位置に置ける。開いたフォルダの外に出すと閉じる
- **ウィジェットの長押し**：メニューとリサイズ枠を出し、指を動かすとドラッグに移る（[5.2](#52-配置できるもの)）
- **削除とアンインストール**：ドラッグ中に上部の「削除」へ落とすとホームから外し、「アンインストール」へ落とすとアンインストールする。まだホームにないもの（検索結果のアプリ、メニューのショートカット）をドラッグしている間、「削除」は「キャンセル」になる。ショートカット・ウィジェット・システムアプリにはアンインストールを出さない。端末の管理者がアプリの操作やアンインストールを禁止しているユーザー（`DISALLOW_APPS_CONTROL`・`DISALLOW_UNINSTALL_APPS`）のアプリにも出さない（Launcher3 の `SecondaryDropTarget` と同じ）
- **フォルダの作成と解除**：アプリやショートカットを別のアプリやショートカットに重ねるとフォルダになる。フォルダの中身が1つになったらフォルダを解除する
- **空いている領域の長押し**：メニューを出す（Launcher3 の `WorkspaceTouchListener` と `WorkspaceLongPressOptions`）。項目は Launcher3 と同じ順で次のとおり（「ホームの設定」はない）。メニューは Launcher3 と同じく、ランチャーが隠れたとき（このランチャーでは `onStop`）に閉じる。ダイアログ形式の画面（壁紙のアプリの選択など）ではランチャーが隠れないので、その間はメニューが残る（Launcher3 でも同じ）
  - 「壁紙とスタイル」：OS の「壁紙とスタイル」を開く（[7. アイコンとテーマ](#7-アイコンとテーマ)）。Launcher3 と同じく `ACTION_SET_WALLPAPER` を開く。開くアプリを決める設定（`wallpaper_picker_package`）は Pixel では端末側が埋めるが、このランチャーでは空なので、受けられるアプリが複数あると選ぶ画面が出る
  - 「ウィジェット」：ウィジェットを追加する（[5.2](#52-配置できるもの)）
  - 「通知ドット」：通知へのアクセスが許可されていない間だけ出す。Launcher3 の「ホームの設定」の「通知ドット」の代わり（[7.5](#75-通知ドット)）。押すとメニューを閉じてダイアログを出す
  - 「アプリのリスト」：[6. 全アプリ一覧](#6-全アプリ一覧) を普段と同じアニメーションで開く（[6.3](#63-気付いてもらうための見せ方)）。2パネル（[5.5](#55-2パネル折りたたみ端末の内側)）では一覧がいつも出ているので、この項目はない

### 5.4 編集モード

編集中はキーボードを下ろし、画面全体を使って編集できるようにする。

- **始まるとき**：ドラッグを始めたとき、ウィジェットのリサイズ枠が出たとき、ウィジェット一覧から追加しようとしたとき
- **終わるとき**：ドロップしたとき、リサイズ中に枠の外をタップしたとき、戻る操作をしたとき、ホームボタンを押したとき、ほかの画面が前に出てランチャーが一時停止したとき（Launcher3 の `onPause` と同じくドラッグを取り消す）
- **終わった後**：検索フィールドにフォーカスを戻し、キーボードを表示する
- **見た目**：Launcher3 の編集中（SpringLoadedState）と同じにする。違いはホームが1つ（縦スクロール）しかないことだけ
  - 編集が始まったら、キーボードが下りきるのを待たずに、すぐキーボードを下ろした状態の大きさ（配置できる範囲の全体）にする
  - 開いているフォルダは、Launcher3 と同じくその場に残り、後ろのホームだけが縮む。編集が終わってキーボードが戻るとき、フォルダがキーボードに重なるなら、キーボードの上に収まるように上にずらす
  - ホーム（見えている範囲）を、上部の削除・アンインストールのボタンの下から、検索フィールドの 76dp 上までに収まるように縮小する。左右には少なくとも 48dp ずつ空ける（Launcher3 で隣のページが見える幅）。縮小は 150ms で、ZOOM_OUT の動き
  - 縮小したホームには、角の丸い背景（アクセント色の 35%）を付け、ドラッグが上にある間は 2dp の枠を付ける
  - 壁紙は Launcher3 のドラッグ中のスクリム（system_neutral1_900 の 20%、150ms の線形）で暗くする
  - 壁紙は Launcher3 と同じく奥行き 15% の分だけぼかす（全アプリ一覧のぼかしと同じ仕組み）
  - リサイズ枠が出ている間は、キーボードを下ろすだけで、ホームの縮小や背景は付けない（Launcher3 でもリサイズ枠は SpringLoadedState にならない）。ドラッグで落とした後に枠が出るときは、キーボードを出さずにそのまま枠に移る
- **戻る操作の扱い**：編集モード中の戻る操作は編集モードを終えるだけにする。[1.4](#14-戻る操作) の入力クリアは行わない
- **キーボード監視の扱い**：編集モード中はキーボードが閉じても出し直さない

### 5.5 2パネル（折りたたみ端末の内側）

Launcher3 と同じく、スマホの大きさのディスプレイと大画面（短い辺が 600dp 以上）のディスプレイの両方を持つ端末（`TYPE_MULTI_DISPLAY`）では、大画面のウィンドウを左右の2パネルにする（`DeviceProfile.isTwoPanels`）。Launcher3 は2ページを並べるが、このランチャーはホームが1ページなので、左を全アプリ一覧、右をホームにする。大画面だけの端末（タブレット）は2パネルにしない。

- 分けるのは画面の真ん中（Launcher3 と同じ）。折り目の位置（`FoldingFeature`）は見ない
- 右のパネルは [5.1](#51-グリッド) のホーム。グリッドは外側の画面と同じなので、畳んでも開いても配置は変わらない
- 左のパネルは全アプリ一覧（[6.4](#64-開いた状態) の並び順と表示）で、いつも出ている。見た目は Launcher3 の大画面の全アプリ一覧のシートと同じ（上の角だけが丸く、画面の下まで伸びて、検索フィールドとキーボードの裏に続く。色は全アプリ一覧のシートと同じ）。ハンドルは、引っ張る操作がないので付けない（その分の余白は残す）。一覧は検索フィールドの上で切れる
- ドラッグ中の削除・アンインストールのボタンは、右のパネル（ホーム）の上に出す
- 検索フィールドは画面の幅いっぱいで、キーボードの直上（[1.3](#13-配置と見た目)）。両方のパネルはその上までにする
- 入力があるときは、左の全アプリ一覧の代わりに検索結果を出す（[2.5](#25-検索結果の表示) と同じく下寄せで、1位が検索フィールドに一番近い）。ホームは右に出たまま
- 全アプリ一覧を開く・閉じる操作（[6.1](#61-開く操作)、[6.6](#66-閉じる操作)）はない
- 左の一覧や検索結果からアイコンを長押ししてドラッグし、右のホームに置ける（[6.4](#64-開いた状態) と違い、一覧は閉じない）
- 折りたたむ・開く、分割画面にする、などで2パネルかどうかが変わったら、Activity を作り直す

## 6. 全アプリ一覧

2パネルの画面（[5.5](#55-2パネル折りたたみ端末の内側)）では、全アプリ一覧は左のパネルにいつも出ている。この章の開閉の操作と見せ方は、それ以外の画面のもの。

ユーザーからは、普段はキーボードの下に全アプリ一覧が隠れていて、検索フィールドごと引き上げると現れる構造に見えるようにする。

### 6.1 開く操作

- 検索フィールドを上にスワイプする
- ホームの配置を一番下までスクロールした状態で、さらに上にスワイプする
  - 配置が画面に収まっていてスクロールしない場合は、ホームのどこからでも上にスワイプすれば開く
  - 慣性スクロール（フリング）で一番下に着いただけでは開かない。指で引っ張ったときだけ開く
- キーボードの上から始めたスワイプは拾えない。キーボードは別のウィンドウだからである

### 6.2 開閉の手触り

- 閾値までは指の動きに抵抗をかけ、少しだけ動かす（引っ掛かっている感じ）
- 閾値を越えた瞬間にハプティックを鳴らし、検索フィールドがクッと持ち上がって、指に追従する動きに切り替わる
- 閾値の手前で指を離したら、バネのように元の位置に戻る
- 閾値を越えてから指を離したら、上端までアニメーションで移動して開く
- キーボードは、閾値を越えて持ち上がるのと同時に下ろす
- 閉じるとき（[6.6](#66-閉じる操作)）も同じ手触りにする。方向が下向きになるだけで、閾値までの抵抗、閾値でのハプティック、手前で離したときに戻る動きは同じ
- 元の状態に戻ったとき（閾値の手前で離したとき、閉じかけて開いたままに戻したとき）は、Launcher3 と同じく何も変えない。入力した語、フォーカス、キーボードはそのまま
- 開閉のアニメーションの途中で触ると、Launcher3 と同じくシートをその場で掴み、指に追従する。離すと同じ決まりで開くか閉じる。タップでも止まったままにはならない

### 6.3 気付いてもらうための見せ方

上に引っ張る操作は、画面のどこにも表示しない。そのかわり、空いている領域の長押しメニューの「アプリ一覧」（[5.3](#53-編集操作launcher3-に準拠)）から開いたときにも、普段と同じアニメーションで開く。検索フィールドが上がって一覧が出てくる動きを見せることで、「キーボードの下に一覧があり、上に引っ張れば出てくる」と気付いてもらう。Launcher3 と同じく、このときは開き始めにタップのハプティック（`TAP_HIGH_EMPHASIS`）を鳴らす。

### 6.4 開いた状態

- 検索フィールドは画面の上端に張り付き、そのすぐ下にハンドル付きのシートがあって、その中が全アプリ一覧になる（Launcher3 の `allAppsSheetForHandheld` のボトムシート。Pixel Launcher と同じ見た目）
- シートの上端は、いつも検索フィールドのすぐ下にある。検索フィールドがキーボードの上から画面の上端へ動くのについて上がり、キーボードの裏に隠れていたシートが出てくるように見せる（Launcher3 と Pixel Launcher では画面の下から出てくるが、このランチャーの「キーボードの下に一覧が隠れている」構造に合わせた）
- 開くにつれて、背景（壁紙とホーム）をぼかす。ぼかしは Launcher3 の奥行き（depth）と同じで、ボトムシートの奥行きで最大 30dp。ホームは 0.97 倍に縮む。ぼかしは指の動きに合わせて少しずつ強くなる。シートはぼかしの上で半透明（Pixel Launcher と同じ色。ライトテーマでは明るく、ダークテーマでは暗い）。端末がウィンドウのぼかしに対応していないときは、Launcher3 と同じく不透明な色（system_accent2_200、ダークテーマでは 800）で、ぼかさない
- フォーカスは外し、キーボードは出さない（[1.4](#14-戻る操作) のキーボード監視も止める）
- **並び順**：アプリ名順（Launcher3 の `AlphabeticalAppsList` と同じ）。スクロールバーのつまみを動かすと、英字は A〜Z、かなは あ・か・さ… の見出しを吹き出しで出し、その見出しに飛ぶ。一覧の中に見出しの行は出さない（Launcher3 と同じ）
- **表示**：各アプリのアイコンとアプリ名。Launcher3 と同じく、テーマアイコンと選んだ形状はホームとフォルダのアイコンにだけ付き、一覧と検索結果のアイコンは通常のアイコンを OS の形で表示する（Pixel Launcher でも同じ）
- **長押し**：[5.3](#53-編集操作launcher3-に準拠) と同じ。メニューが出て、一定距離動かすとドラッグに移る。ドラッグが始まったら一覧を閉じ、ホームの配置の表示に切り替える

### 6.5 一覧内の検索

- 検索フィールドをタップすると、フォーカスが当たってキーボードが出て、一覧内の検索になる
- 並び順と Enter での起動は [2.3](#23-並び順) と [2.4](#24-enter-で起動) と同じ。学習も [3](#3-起動の学習) と同じく記録する
- 結果はフィールドの直下から上詰めで並べる。1位がフィールドに一番近い位置に来る
- 一覧と検索結果の切り替えにアニメーションは付けない（[2.5](#25-検索結果の表示) と同じ理由）
- 戻る操作は普通の挙動にする。キーボードが出ているときの1回目はキーボードを閉じるだけで、入力は残し、絞り込んだ一覧をフォーカスなしで表示する。2回目で一覧を閉じる（[6.6](#66-閉じる操作)）
- 一覧内の検索中は、[1.4](#14-戻る操作) のキーボード監視（閉じたら入力をクリアして出し直す）を行わない

### 6.6 閉じる操作

- OS の戻る操作（キーボードが出ているときは、1回目でキーボードが閉じ、2回目で一覧が閉じる）
- 検索フィールドを下にスワイプする
- 一覧を一番上までスクロールした状態で、さらに下にスワイプする。一覧の中で検索しているときは、検索結果を一番上までスクロールした状態で（Launcher3 の `getActiveRecyclerView`）
- ホームボタン
- 閉じたら入力をクリアし、検索フィールドをキーボードの直上に戻して、フォーカスを当ててキーボードを出す
- 一覧からアプリを起動した場合、ホームに戻ってきたときは一覧を閉じた状態にする

## 7. アイコンとテーマ

見た目の設定は、できるだけ OS 側に任せ、ランチャーでは設定を持たない。

### 7.1 壁紙

- 壁紙の選択は OS の「壁紙とスタイル」に任せる
- ランチャーは背景を透明にして壁紙を見せるだけにする（テーマで `windowShowWallpaper` を有効にする）
- 空いている領域の長押しメニューの「壁紙とスタイル」から開けるようにする（[5.3](#53-編集操作launcher3-に準拠)）

### 7.2 テーマカラー

- 色の決め方（壁紙から自動で決めるか、基本の色を選ぶか）は OS の設定に任せる
- 壁紙の上に出る文字（検索結果のアプリ名）とステータスバー・ナビゲーションバーのアイコンは、Launcher3 と同じく壁紙の色のヒントで決める（`WallpaperColorHints`、`Themes.getActivityThemeRes`）。暗い文字が合う壁紙では黒い文字（影なし）、それ以外では白い文字に影。ライトモードかどうかでは決めない。壁紙が変わってヒントが変わると、ランチャーの画面を作り直す
- ランチャー自身の UI は、システムの dynamic color に合わせる
  - 対象：検索フィールド、候補の強調表示、メニューなど

### 7.3 テーマアイコンとアイコン形状

- オン/オフと形状の選択は、OS の「壁紙とスタイル」で行う
- そのために、AOSP の Launcher3 と同じ形の ContentProvider を公開する（詳細は付録の実装メモ）
  - **テーマアイコン**：オンのとき、ホームとフォルダのアイコンは、アプリが用意した単色アイコン（`AdaptiveIconDrawable.getMonochrome()`）をシステムのパレットで塗って表示する。検索結果と全アプリ一覧には付けない（[6.4](#64-開いた状態)）。初期値はオン
  - **単色アイコンを用意していないアプリ**：テーマアイコンがオンのときは、単色アイコンを自動生成して同じように塗る（Pixel Launcher と同じ挙動）
  - **アイコン形状**：選んだ形状で、ホームとフォルダのアイコンを切り抜く。テーマアイコンにも通常のアイコンにも適用する。初期値は円
- **実装の基準**：アイコンの生成と表示は、基準タグの AOSP Launcher3 の実装に従う（[Launcher3 からの取り込み方針](launcher3-porting.md)）
  - 対象：テーマアイコン、単色アイコンの自動生成、形状での切り抜き
  - 参照先：Launcher3 と、そのアイコン処理ライブラリ `frameworks/libs/systemui/iconloaderlib`（`MonochromeIconFactory` など）
  - 自動生成が Launcher3 で機能フラグの裏にあり、既定でオフになっている場合でも、このランチャーでは有効にする
- **適用範囲**：アイコンを表示するすべての場所
  - ホームの配置
  - フォルダのプレビューと中身
  - 検索結果
  - 全アプリ一覧
- **位置付け**：これは公開 API ではなく、AOSP 内部の約束事である。OS の更新で使えなくなる可能性がある
- **進め方**：
  - 実装の早い段階で、Pixel（Android 17）の「壁紙とスタイル」に項目が出るかを実機で確かめる
  - 出なかった場合や使えなくなった場合は、自前の設定に切り替える

### 7.4 対応言語

- 既定は英語。主要言語に翻訳する
- 「アプリを検索」「アプリ情報」「削除」「アンインストール」は、Launcher3 の各言語の訳をそのまま使う（Pixel と同じ用語にするため）

### 7.5 通知ドット

Launcher3 と同じく、通知があるアプリのアイコンの右上にドットを付ける。

- 対象はホーム、フォルダの中、全アプリ一覧、検索結果のアイコン。フォルダは、中のどれかに通知があればフォルダのアイコンにもドットを付ける。ホームに置いたアプリのショートカットは、そのショートカットに向けた通知があるときだけ付く
- 数える通知も Launcher3 と同じ。チャンネルがドットを許していないもの、タイトルも本文もないもの、グループのまとめの通知は数えない
- 通知が来たり消えたりすると、表示中のアイコンもすぐ変わる（ドットは拡大・縮小のアニメーションで出入りする）
- 色はテーマの3番目のアクセント色（ライトは `system_accent3_200`、ダークは `system_accent3_100`）。位置はアイコン形状の右上の角に合わせる
- OS の「アプリアイコンの通知ドット」がオフなら出さない（Launcher3 と同じく、通知の受け取りをやめる。オンに戻すと再開する）
- ドットには OS の「通知へのアクセス」の許可が要る（Pixel Launcher はシステムアプリなので要らない）。許可がない間は、空いている場所の長押しメニュー（5.3）に「通知ドット」を出す。押すと Launcher3 の設定画面と同じ「通知へのアクセスが必要です」のダイアログを出し、「設定を変更」で OS の通知へのアクセスの画面を開く。許可されると項目は出なくなる。OS の通知ドットの設定がオフのときも出さない
- 長押しメニューに通知の中身を並べる行（Launcher3 の通知の行）は入れない。Pixel Launcher にもないため

## 8. 対象外としたもの

| 項目 | 理由 |
|---|---|
| 頭文字一致（`gm` で Google Maps など） | ユーザーが登録する検索文字列で足りる |
| 完全一致の固定割り当て | 検索文字列の完全一致を最優先にしているので、登録すれば同じことができる |
| アプリ以外の検索（ショートカット、連絡先、Web など） | 入れない方針 |
| フォルダの検索 | 入れない方針 |
| キーボードで狭くなる配置エリアへの対策 | 作ってから判断する |
| ウィジェット内部のスクロール | 考慮しない |
| ホームの配置でのアプリ名表示 | 表示しない代わりに縦を詰める |
| フォルダ名 | 付けられない |
| 仕事用プロファイル | 当面は非対応。アプリと `UserHandle` の組で記録しているので、後から追加できる |
| Private Space | 非対応。`ACCESS_HIDDEN_PROFILES` を宣言しないので、中のアプリは見えない。このランチャーを既定にしている間は、Private Space をこのランチャーから開けない |
| 設定画面 | 置かない。検索文字列の編集は長押しメニューから行う。見た目の設定は「壁紙とスタイル」に任せる。既定のホームアプリの選択は OS の設定から行う |
| 学習データのリセット、検索文字列の書き出し・読み込み | 設定画面を置かないので入れない |
| 最近使ったアプリ（App Switcher）の画面 | 作れない。この画面は既定のランチャーに関係なく Pixel Launcher（Quickstep）が描く。TextLauncher を既定にしている間は、Quickstep の代替の画面（`RecentsActivity` に `OverviewBlurFallbackStyle`）になり、背景は壁紙のぼかしではなく不透明な色（`overviewScrimColorFallback`）になる |

## 付録: 実装メモ

- Manifest
  - ホームの Activity に `MAIN` + `HOME` + `DEFAULT` の intent-filter を付ける
  - `launchMode="singleTask"` にする
  - `windowSoftInputMode="stateAlwaysVisible|adjustResize"` にする
- パッケージの可視性：`<queries>` に `MAIN`/`LAUNCHER` の intent を宣言する
- アプリの追加・削除・更新は `LauncherApps.Callback` で検知する
- キーボードの表示：`WindowInsetsControllerCompat.show(WindowInsetsCompat.Type.ime())` を使う
- キーボードの表示状態の監視：`WindowInsetsCompat` の IME の可視状態を使う
- 検索フィールド上の縦スワイプの検出：
  - 親の ViewGroup の `onInterceptTouchEvent` で検出する
  - touch slop を越え、かつ縦の移動量が横より大きくなったら、親がタッチを横取りする（EditText 側には `ACTION_CANCEL` が届く）
  - 1行の EditText は縦にスクロールしないので競合しない。タップによるフォーカス、横方向のカーソル移動、長押しの選択はそのまま EditText に届く
- ホームの配置の、端に着いた後の引っ張りの検出：
  - 指を置いた時点でホームがもう下にスクロールできないときだけ、上向きのスワイプを全アプリ一覧の開閉として拾う（Launcher3 の `AllAppsSwipeController.canInterceptTouch` と同じく、タッチの始まりで決める）。フリングで一番下に着いただけでは、そのタッチは開閉にならない
  - 全アプリ一覧の一番上での引っ張りも同じく、指を置いた時点で一覧が一番上にあるとき（`shouldContainerScroll`）だけ拾う
- 開閉の動き：
  - 引っ掛かりは、閾値（48dp）までの移動量に減衰（Launcher3 の `OverScroll.dampedScroll`）をかけて表現する。閾値を越えたら、検索フィールドは 150ms で指に追いつく
  - 戻る動きと開き切る動きは、Launcher3 と同じく離したときの速度から長さを決めるアニメーション（`BaseSwipeDetector.calculateDuration`、`scrollInterpolatorForVelocity`）にする
  - キーボードの開閉は `WindowInsetsAnimationCompat` で同期させる
- ハプティック：Launcher3 と同じく、`msdllib` の `SWIPE_THRESHOLD_INDICATOR` を鳴らす（[Launcher3 からの取り込み方針](launcher3-porting.md) の「ハプティックを鳴らす場所」）
- 「壁紙とスタイル」との連携（[7.3](#73-テーマアイコンとアイコン形状)）：
  - AOSP の `android-17.0.0_r1` のソースで確認した内容である（Launcher3 の `graphics/LauncherCustomizationProvider.kt`、`graphics/GridCustomizationsProxy.java`、`shapes/ShapesProvider.kt`、ThemePicker の `res/values/strings.xml`）
  - **見つけてもらう仕組み**：ホームの Activity に meta-data を付け、値に Provider の authority（Launcher3 では `<applicationId>.grid_control`）を入れる
    - `com.android.launcher3.grid.control`：Launcher3 の manifest にあるもの
    - `com.android.launcher3.themedicon.option`：ThemePicker がテーマアイコンの問い合わせ先を探すのに使うもの
  - **権限**：Provider は exported にし、呼び出し元が `android.permission.BIND_WALLPAPER` を持っているかをコード側で確かめる（Launcher3 と同じ）
  - **読み出し（query）**：
    - `/icon_themed`、`/get_icon_themed`：`boolean_value` 列（1/0）を持つ1行を返す
    - `/shape_options`：列 `shape_key`、`shape_title`、`path`（100×100 の SVG パス）、`is_default`。選んでいる形状が `is_default` になる
    - `/list_options`（グリッド）：null を返す。グリッドの選択肢は出さない
    - `/workspace_items_label_hidden`（ホームのアプリ名を隠す設定。Android 17 で追加）：null を返す。このランチャーでは常に隠すため
  - **書き込み（update）**：成功したら 1 を返し、`notifyChange` する
    - `/icon_themed`、`/set_icon_themed`：`boolean_value` を保存する
    - `/shape`：`shape_key` を保存する
    - `/default_grid`：0 を返す（グリッドは変えさせない）
  - **形状の選択肢**（`ShapesProvider.kt`）：`circle`（初期値）、`square`、`four_sided_cookie`、`seven_sided_cookie`、`arch` の5つ。SVG パスは取り込み時にそのまま移植する
  - **プレビュー**（`call` の `get_preview`）：Launcher3 はホームのプレビューを描いて返す。まずは null を返し、「壁紙とスタイル」側の表示に問題が出るかを実機で確かめる
  - 既知の問題（サードパーティのランチャーの実装例 [pie-launcher-remake #28](https://github.com/jgoedde/pie-launcher-remake/issues/28) より）：「壁紙とスタイル」は接続先のランチャーをキャッシュする。ホームアプリを切り替えた直後は、そのプロセスが終わるまで前のランチャーにつながることがある
