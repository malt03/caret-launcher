# TextLauncher 仕様書

## コンセプト

常にキーボードが表示されている、テキスト入力中心の Android ホームアプリ（ランチャー）。

- ホーム画面では常に検索フィールドにフォーカスが当たり、キーボードが表示されている
- 入力した文字でアプリをインクリメンタルサーチし、Enter で即起動する
- 未入力のときは、ユーザーが自由に配置したアプリ・ウィジェット・フォルダが表示される

前提環境は minSdk 33 / targetSdk 37。

---

## 1. 検索フィールドとキーボード

### 1.1 常時フォーカス

検索フィールドには常にフォーカスが当たり、キーボードが表示されている。以下のタイミングでフォーカスを当て、キーボードを表示し直す。

| タイミング | 主なフック |
|---|---|
| アプリからホームに戻ったとき | `onResume` |
| ホーム画面上でホームボタンを押したとき | `onNewIntent` |
| ロック解除後、通知シェードを閉じた後など、ウィンドウにフォーカスが戻ったとき | `onWindowFocusChanged(true)` |
| ホーム画面が前面のままキーボードが閉じられたとき | IME 表示状態の監視（[1.4](#14-戻る操作) を参照） |
| 編集モードが終わったとき | [5.4](#54-編集モード) を参照 |
| 全アプリ一覧を閉じたとき | [6.6](#66-閉じる操作) を参照 |

例外として、次の間はキーボードを下ろし、フォーカスも外す。

- 編集モード中（[5.4](#54-編集モード)）
- 全アプリ一覧を開いていて、ユーザーがまだ検索フィールドをタップしていない間（[6.4](#64-開いた状態)）

### 1.2 入力のクリア

- ランチャーが前面に戻るたびに入力をクリアする（アプリから戻る、ホームボタン、ロック解除のいずれも含む）
- アプリを起動したときもクリアする
- 戻る操作をしたときもクリアする（[1.4](#14-戻る操作) を参照）

### 1.3 配置と見た目

- 検索フィールドはキーボードの直上に置く（IME の inset に追従させる）
- フォーカスが当たっていることが UI で分かるようにする
- Enter で起動される候補（検索結果の1位）は強調表示する（[2.4](#24-enter-で起動) を参照）

### 1.4 戻る操作

戻るジェスチャーは完全には禁止できない。以下の方法で実質的に無効化する。

1. **Activity の戻る操作**
   `OnBackPressedCallback` で消費し、何もしない。
2. **キーボードが閉じる動作**
   キーボード表示中の戻る操作はキーボード（IME）側が先に受け取って自分を閉じるため、アプリからは止められない。そこで、ホーム画面が前面にある間にキーボードが閉じられたことを検知したら、入力をクリアしてすぐに表示し直す。結果として、戻る操作は「入力クリア」として働く。閉じるアニメーションが一瞬見える可能性がある。
3. **ジェスチャー除外領域**（`setSystemGestureExclusionRects`）
   使わない。除外できるのは各辺で縦 200dp までで、しかも対象はアプリ自身のウィンドウだけなので、キーボードの領域には効かない。

## 2. アプリ検索

### 2.1 検索対象

- 検索対象はランチャーに表示されるアプリ（`LauncherApps.getActivityList`）のみ
- 対象は個人用プロファイルのアプリだけ。仕事用プロファイルと Private Space には対応しない（[8. 対象外](#8-対象外としたもの) を参照）
- アプリごとの照合文字列は次の2種類
  - アプリ名（ラベル）
  - ユーザーが設定した検索文字列（1つのアプリに複数設定できる。[4. 検索文字列の編集](#4-検索文字列の編集) を参照）
- アプリショートカット、連絡先、設定項目、Web 検索、フォルダなどは検索対象にしない（[8. 対象外](#8-対象外としたもの) を参照）

### 2.2 正規化

入力文字列と照合文字列の両方に、同じ正規化をかけてから比較する。

1. NFKC 正規化（全角英数字を半角に、半角カナを全角に揃える）
2. 小文字化
3. カタカナをひらがなに変換（`ァ`(U+30A1)〜`ヶ`(U+30F6) から 0x60 を引く）

これにより、カタカナのアプリ名や検索文字列は、ひらがなで入力しても一致する。漢字の読みは自動では取得しないので、ユーザーがひらがなの検索文字列を登録して補う。

### 2.3 並び順

入力文字列 `q`（正規化済み）に対して、各アプリの照合文字列のうち最も強い一致の種類を、そのアプリの一致種別とする。

| 一致種別 | 条件 |
|---|---|
| 完全一致 | 照合文字列 == `q` |
| 前方一致 | 照合文字列が `q` で始まる |
| 部分一致 | 照合文字列が `q` を含む |

候補は次の優先順位（グループ）で並べる。

1. **完全一致**：グループ内は学習スコアの降順
2. **学習あり**：完全一致以外で、`q` に対する学習スコアが 0 より大きいアプリ。スコアの降順
3. **前方一致**
4. **部分一致**

3と4のグループ内はアプリ名順で並べる。

> 学習スコアは `q` と完全に同じ入力文字列で起動した記録だけを使う。`q` を先頭に含む別の入力（たとえば `q` が `s` のときの `sl`）の記録は使わない。

### 2.4 Enter で起動

- 候補の1位を Enter で起動する（IME のアクションは `actionGo`）
- 日本語 IME で変換中に押した Enter は確定として扱われ、起動はしない（IME 側の標準動作）
- 候補が0件、または未入力のときは何もしない
- 候補をタップしても起動できる

### 2.5 検索結果の表示

- 入力があるときは、ホームの配置エリアの代わりに検索結果を表示する
- 見た目は Launcher3 のアプリ一覧と同じグリッドにする。各セルはアイコンと、その下のアプリ名
  - 列数は、ホームのグリッド（[5.1](#51-グリッド)）と同じ
  - ホームの配置ではアプリ名を出さないが、検索結果では出す
- 下寄せにし、1位を検索フィールドに一番近い位置（一番下の行の左端）に置く。2位以降は右へ並べ、行が埋まったら上の行に続ける

## 3. 起動の学習

### 3.1 記録する内容

検索結果からアプリを起動したとき、次の組み合わせを記録する。

`(正規化済みの入力文字列, アプリ) → (score, lastUpdated)`

- アプリは `ComponentName` と `UserHandle` で識別する
- 未入力状態のホーム配置から起動した場合は記録しない

### 3.2 スコア（直近ほど重くする頻度）

起動回数をそのまま使うのではなく、時間とともに減衰するスコアを使う。半減期を `H` とする。

- **起動したとき**：`score = score × 0.5^((now − lastUpdated) / H) + 1` を計算し、`lastUpdated = now` にする
- **並べ替えるとき**：その時点の値として `score × 0.5^((now − lastUpdated) / H)` を使う

この方式の特徴は次のとおり。

- 起動履歴を全件保存しなくても、1レコードあたり2つの値で「回数」と「新しさ」の両方を表せる
- しばらく使わなかった組み合わせは自然に順位が下がる
- `H` の初期値は 14 日とし、使いながら調整する
- 計算後のスコアが一定値（例: 0.05）を下回ったレコードは削除する

## 4. 検索文字列の編集

- アプリごとに検索文字列を複数登録・削除できる
- 編集の入口は、アプリの長押しメニューの「検索文字列を編集」（[5.3](#53-編集操作launcher3-に準拠)）。ホーム、検索結果、全アプリ一覧のどこからでも開ける
- 設定画面は置かない（[8. 対象外](#8-対象外としたもの)）。見た目の設定は「壁紙とスタイル」に任せる（[7. アイコンとテーマ](#7-アイコンとテーマ)）
- 登録した文字列は [2.2](#22-正規化) と同じ正規化をかけて照合する。カタカナで登録しても、ひらがなと同じように扱われる

## 5. ホームの配置（未入力時）

ユーザーが任意のアプリ、ウィジェット、フォルダを配置できる。基本は AOSP の Launcher3 の標準的な設定と操作に合わせ、以下に書いた点だけを変える。手触りに関わる部分は Launcher3 の実装を持ってくる（[Launcher3 からの取り込み方針](launcher3-porting.md)）。

### 5.1 グリッド

- 列数、アイコンサイズ、セルの幅は、Launcher3 の標準のグリッド設定（`res/xml/device_profiles.xml` の `grid-option`）に合わせる。具体的な値は実装時に参照して決める
- アプリ名は表示しない。その分、セルの高さを詰める（アイコンと余白だけ）
- 行数に上限はなく、画面に収まらない場合は縦スクロールする（Launcher3 の横方向のページ切り替えの代わり）
- キーボードが表示されているぶん配置エリアは狭くなるが、初期実装では対策しない。実際に作ってから判断する

### 5.2 配置できるもの

- **アプリ**：1セルを使う。アプリ名は表示しない
- **ウィジェット**：複数セルを使う。`AppWidgetHost` で表示し、追加時のサイズとリサイズは Launcher3 に合わせる。ウィジェット内部のスクロールは考慮しない
- **フォルダ**：
  - 名前は付けられない
  - アイコンは中のアプリのプレビューにする（Launcher3 と同様）
  - タップすると中身を開く。中のアプリもアプリ名は表示しない
  - フォルダ自体は検索対象にしない

### 5.3 編集操作（Launcher3 に準拠）

- **アプリの長押し**（ホーム上でも検索結果でも同じ）：
  - その場にメニューを出す
  - 指を離さずに一定距離動かすと、メニューを閉じてドラッグに移る（Pixel Launcher と同じ動き）
  - メニューの項目は「検索文字列を編集」と「アプリ情報」
- **検索結果からのドラッグ**：ドラッグが始まった時点で入力をクリアし、ホームの配置の表示に切り替える。そのままホームに置ける（Launcher3 でアプリ一覧からドラッグする操作に相当）
- **フォルダとウィジェットの長押し**：ドラッグが始まり、移動できる。ウィジェットはリサイズもできる
- **削除とアンインストール**：ドラッグ中に上部の「削除」へ落とすとホームから外し、「アンインストール」へ落とすとアンインストールする
- **フォルダの作成と解除**：アプリを別のアプリに重ねるとフォルダになる。フォルダの中身が1つになったらフォルダを解除する
- **空いている領域の長押し**：メニューを出す。項目は次のとおり
  - 「ウィジェットの追加」
  - 「アプリ一覧」：[6. 全アプリ一覧](#6-全アプリ一覧) を普段と同じアニメーションで開く（[6.3](#63-気付いてもらうための見せ方)）
  - 「壁紙とスタイル」：OS の「壁紙とスタイル」を開く（[7. アイコンとテーマ](#7-アイコンとテーマ)）

### 5.4 編集モード

編集中はキーボードを下ろし、画面全体を使って編集できるようにする。

- **始まるとき**：ドラッグを始めたとき、ウィジェットのリサイズを始めたとき、ウィジェット一覧から追加しようとしたとき
- **終わるとき**：ドロップしたとき、リサイズ中に枠の外をタップしたとき、戻る操作をしたとき、ホームボタンを押したとき
- **終わった後**：検索フィールドにフォーカスを戻し、キーボードを表示する
- **戻る操作の扱い**：編集モード中の戻る操作は編集モードを終えるだけにする。[1.4](#14-戻る操作) の入力クリアは行わない
- **キーボード監視の扱い**：編集モード中はキーボードが閉じても出し直さない

## 6. 全アプリ一覧

ユーザーからは、普段はキーボードの下に全アプリ一覧が隠れていて、検索フィールドごと引き上げると現れる構造に見えるようにする。

### 6.1 開く操作

- 検索フィールドを上にスワイプする
- ホームの配置を一番下までスクロールした状態で、さらに上にスワイプする
  - 配置が画面に収まっていてスクロールしない場合は、ホームのどこからでも上にスワイプすれば開く
  - 慣性スクロール（フリング）で一番下に着いただけでは開かない。指で引っ張ったときだけ開く
- キーボードの上から始めたスワイプは拾えない。キーボードは別のウィンドウだからである

### 6.2 開閉の手触り

- 閾値までは指の動きに抵抗をかけ、少しだけ動かす（引っ掛かっている感じ）
- 閾値を越えた瞬間にハプティックを鳴らし、検索フィールドがクッと持ち上がって、指に追従する動きに切り替わる
- 閾値の手前で指を離したら、バネのように元の位置に戻る
- 閾値を越えてから指を離したら、上端までアニメーションで移動して開く
- キーボードは、閾値を越えて持ち上がるのと同時に下ろす
- 閉じるとき（[6.6](#66-閉じる操作)）も同じ手触りにする。方向が下向きになるだけで、閾値までの抵抗、閾値でのハプティック、手前で離したときに戻る動きは同じ

### 6.3 気付いてもらうための見せ方

上に引っ張る操作は、画面のどこにも表示しない。そのかわり、空いている領域の長押しメニューの「アプリ一覧」（[5.3](#53-編集操作launcher3-に準拠)）から開いたときにも、普段と同じアニメーションで開く。検索フィールドが上がって一覧が出てくる動きを見せることで、「キーボードの下に一覧があり、上に引っ張れば出てくる」と気付いてもらう。

### 6.4 開いた状態

- 検索フィールドは画面の上端に張り付き、その下全体が全アプリ一覧になる
- フォーカスは外し、キーボードは出さない（[1.4](#14-戻る操作) のキーボード監視も止める）
- **並び順**：アプリ名順。英字は A〜Z、かなは あ・か・さ… の見出しを付け、見出しに飛べるスクロールバーを付ける
- **表示**：各アプリのアイコンとアプリ名
- **長押し**：[5.3](#53-編集操作launcher3-に準拠) と同じ。メニューが出て、一定距離動かすとドラッグに移る。ドラッグが始まったら一覧を閉じ、ホームの配置の表示に切り替える

### 6.5 一覧内の検索

- 検索フィールドをタップすると、フォーカスが当たってキーボードが出て、一覧内の検索になる
- 並び順と Enter での起動は [2.3](#23-並び順) と [2.4](#24-enter-で起動) と同じ。学習も [3](#3-起動の学習) と同じく記録する
- 結果はフィールドの直下から上詰めで並べる。1位がフィールドに一番近い位置に来る
- 戻る操作は普通の挙動にする。キーボードが出ているときの1回目はキーボードを閉じるだけで、入力は残し、絞り込んだ一覧をフォーカスなしで表示する。2回目で一覧を閉じる（[6.6](#66-閉じる操作)）
- 一覧内の検索中は、[1.4](#14-戻る操作) のキーボード監視（閉じたら入力をクリアして出し直す）を行わない

### 6.6 閉じる操作

- OS の戻る操作（キーボードが出ているときは、1回目でキーボードが閉じ、2回目で一覧が閉じる）
- 検索フィールドを下にスワイプする
- 一覧を一番上までスクロールした状態で、さらに下にスワイプする
- ホームボタン
- 閉じたら入力をクリアし、検索フィールドをキーボードの直上に戻して、フォーカスを当ててキーボードを出す
- 一覧からアプリを起動した場合、ホームに戻ってきたときは一覧を閉じた状態にする

## 7. アイコンとテーマ

見た目の設定は、できるだけ OS 側に任せ、ランチャーでは設定を持たない。

### 7.1 壁紙

- 壁紙の選択は OS の「壁紙とスタイル」に任せる
- ランチャーは背景を透明にして壁紙を見せるだけにする（テーマで `windowShowWallpaper` を有効にする）
- 空いている領域の長押しメニューの「壁紙とスタイル」から開けるようにする（[5.3](#53-編集操作launcher3-に準拠)）

### 7.2 テーマカラー

- 色の決め方（壁紙から自動で決めるか、基本の色を選ぶか）は OS の設定に任せる
- ランチャー自身の UI は、システムの dynamic color に合わせる
  - 対象：検索フィールド、候補の強調表示、メニューなど

### 7.3 テーマアイコンとアイコン形状

- オン/オフと形状の選択は、OS の「壁紙とスタイル」で行う
- そのために、AOSP の Launcher3 と同じ形の ContentProvider を公開する（詳細は付録の実装メモ）
  - **テーマアイコン**：オンのとき、アプリが用意した単色アイコン（`AdaptiveIconDrawable.getMonochrome()`）をシステムのパレットで塗って表示する。初期値はオン
  - **単色アイコンを用意していないアプリ**：テーマアイコンがオンのときは、単色アイコンを自動生成して同じように塗る（Pixel Launcher と同じ挙動）
  - **アイコン形状**：選んだ形状で、すべてのアイコンを切り抜く。テーマアイコンにも通常のアイコンにも適用する。初期値は円
- **実装の基準**：アイコンの生成と表示は、基準タグの AOSP Launcher3 の実装に従う（[Launcher3 からの取り込み方針](launcher3-porting.md)）
  - 対象：テーマアイコン、単色アイコンの自動生成、形状での切り抜き
  - 参照先：Launcher3 と、そのアイコン処理ライブラリ `frameworks/libs/systemui/iconloaderlib`（`MonochromeIconFactory` など）
  - 自動生成が Launcher3 で機能フラグの裏にあり、既定でオフになっている場合でも、このランチャーでは有効にする
- **適用範囲**：アイコンを表示するすべての場所
  - ホームの配置
  - フォルダのプレビューと中身
  - 検索結果
  - 全アプリ一覧
- **位置付け**：これは公開 API ではなく、AOSP 内部の約束事である。OS の更新で使えなくなる可能性がある
- **進め方**：
  - 実装の早い段階で、Pixel（Android 17）の「壁紙とスタイル」に項目が出るかを実機で確かめる
  - 出なかった場合や使えなくなった場合は、自前の設定に切り替える

## 8. 対象外としたもの

| 項目 | 理由 |
|---|---|
| 頭文字一致（`gm` で Google Maps など） | ユーザーが登録する検索文字列で足りる |
| 完全一致の固定割り当て | 検索文字列の完全一致を最優先にしているので、登録すれば同じことができる |
| アプリ以外の検索（ショートカット、連絡先、Web など） | 入れない方針 |
| フォルダの検索 | 入れない方針 |
| キーボードで狭くなる配置エリアへの対策 | 作ってから判断する |
| ウィジェット内部のスクロール | 考慮しない |
| ホームの配置でのアプリ名表示 | 表示しない代わりに縦を詰める |
| フォルダ名 | 付けられない |
| 仕事用プロファイル | 当面は非対応。アプリと `UserHandle` の組で記録しているので、後から追加できる |
| Private Space | 非対応。`ACCESS_HIDDEN_PROFILES` を宣言しないので、中のアプリは見えない。このランチャーを既定にしている間は、Private Space をこのランチャーから開けない |
| 設定画面 | 置かない。検索文字列の編集は長押しメニューから行う。見た目の設定は「壁紙とスタイル」に任せる。既定のホームアプリの選択は OS の設定から行う |
| 学習データのリセット、検索文字列の書き出し・読み込み | 設定画面を置かないので入れない |

## 付録: 実装メモ

- Manifest
  - ホームの Activity に `MAIN` + `HOME` + `DEFAULT` の intent-filter を付ける
  - `launchMode="singleTask"` にする
  - `windowSoftInputMode="stateAlwaysVisible|adjustResize"` にする
- パッケージの可視性：`<queries>` に `MAIN`/`LAUNCHER` の intent を宣言する
- アプリの追加・削除・更新は `LauncherApps.Callback` で検知する
- キーボードの表示：`WindowInsetsControllerCompat.show(WindowInsetsCompat.Type.ime())` を使う
- キーボードの表示状態の監視：`WindowInsetsCompat` の IME の可視状態を使う
- 検索フィールド上の縦スワイプの検出：
  - 親の ViewGroup の `onInterceptTouchEvent` で検出する
  - touch slop を越え、かつ縦の移動量が横より大きくなったら、親がタッチを横取りする（EditText 側には `ACTION_CANCEL` が届く）
  - 1行の EditText は縦にスクロールしないので競合しない。タップによるフォーカス、横方向のカーソル移動、長押しの選択はそのまま EditText に届く
- ホームの配置の、端に着いた後の引っ張りの検出：
  - スクロールする View の親で `NestedScrollingParent3` を実装する
  - `onNestedScroll` の `dyUnconsumed` を使う。`type == TYPE_TOUCH` のときだけ拾い、フリングは無視する
  - 全アプリ一覧の一番上での引っ張りも同じ仕組みで拾う
- 開閉の動き：
  - 引っ掛かりは、閾値までの移動量に減衰をかけて表現する
  - 戻る動きと開き切る動きは `SpringAnimation` を使う
  - キーボードの開閉は `WindowInsetsAnimationCompat` で同期させる
- ハプティック：API 34 以上は `HapticFeedbackConstants.GESTURE_THRESHOLD_ACTIVATE`、API 33 は `CONFIRM` を使う
- 「壁紙とスタイル」との連携（[7.3](#73-テーマアイコンとアイコン形状)）：
  - AOSP の `android-17.0.0_r1` のソースで確認した内容である（Launcher3 の `graphics/LauncherCustomizationProvider.kt`、`graphics/GridCustomizationsProxy.java`、`shapes/ShapesProvider.kt`、ThemePicker の `res/values/strings.xml`）
  - **見つけてもらう仕組み**：ホームの Activity に meta-data を付け、値に Provider の authority（Launcher3 では `<applicationId>.grid_control`）を入れる
    - `com.android.launcher3.grid.control`：Launcher3 の manifest にあるもの
    - `com.android.launcher3.themedicon.option`：ThemePicker がテーマアイコンの問い合わせ先を探すのに使うもの
  - **権限**：Provider は exported にし、呼び出し元が `android.permission.BIND_WALLPAPER` を持っているかをコード側で確かめる（Launcher3 と同じ）
  - **読み出し（query）**：
    - `/icon_themed`、`/get_icon_themed`：`boolean_value` 列（1/0）を持つ1行を返す
    - `/shape_options`：列 `shape_key`、`shape_title`、`path`（100×100 の SVG パス）、`is_default`。選んでいる形状が `is_default` になる
    - `/list_options`（グリッド）：null を返す。グリッドの選択肢は出さない
    - `/workspace_items_label_hidden`（ホームのアプリ名を隠す設定。Android 17 で追加）：null を返す。このランチャーでは常に隠すため
  - **書き込み（update）**：成功したら 1 を返し、`notifyChange` する
    - `/icon_themed`、`/set_icon_themed`：`boolean_value` を保存する
    - `/shape`：`shape_key` を保存する
    - `/default_grid`：0 を返す（グリッドは変えさせない）
  - **形状の選択肢**（`ShapesProvider.kt`）：`circle`（初期値）、`square`、`four_sided_cookie`、`seven_sided_cookie`、`arch` の5つ。SVG パスは取り込み時にそのまま移植する
  - **プレビュー**（`call` の `get_preview`）：Launcher3 はホームのプレビューを描いて返す。まずは null を返し、「壁紙とスタイル」側の表示に問題が出るかを実機で確かめる
  - 既知の問題（サードパーティのランチャーの実装例 [pie-launcher-remake #28](https://github.com/jgoedde/pie-launcher-remake/issues/28) より）：「壁紙とスタイル」は接続先のランチャーをキャッシュする。ホームアプリを切り替えた直後は、そのプロセスが終わるまで前のランチャーにつながることがある
